1. El problema: un número no basta

Un modelo de aprendizaje automático casi siempre responde con un solo número: “el gasto de marzo será $1.200 millones” o “esta transacción es fraude con probabilidad 0,83”. Para decidir, eso se queda corto. Quien aprueba un presupuesto o prioriza una revisión de fraude necesita saber qué tan lejos puede estar la realidad de esa predicción.

Las salidas habituales no resuelven el problema:

  • Los intervalos clásicos de la estadística suponen que los datos siguen una distribución normal, lo que casi nunca pasa.
  • Las probabilidades de modelos como XGBoost sirven para ordenar los casos (este es más riesgoso que aquel), pero no son confiables como porcentaje. En el notebook 02 del curso vimos que con scale_pos_weight se inflan todavía más.
Conformal prediction mide qué tan grandes son los errores del modelo en datos que no vio, y con eso le pone un margen de seguridad a cada predicción, con una promesa comprobable: acertar al menos el 90 % de las veces (o el porcentaje que se elija).

2. La idea, con una analogía

Un empleado nuevo estima el valor de las facturas a simple vista. Para saber cuánto confiar en él:

  1. Le muestro 100 facturas cuyo valor real ya conozco y que él nunca ha visto.
  2. Anoto cuánto se equivocó en cada una.
  3. Ordeno los errores de menor a mayor y miro el error número 90. Digamos que es de $80 mil.
  4. Desde hoy, cuando diga “esta factura vale $1 millón”, yo digo: “está entre $920 mil y $1.080.000”, y acierto el 90 % de las veces.

No necesito saber cómo piensa el empleado: solo medí sus errores en casos que no había visto. Eso es exactamente conformal prediction.

3. Por qué funciona

Se ponen en fila los errores de calibración, de menor a mayor. El caso nuevo es “uno más del grupo”: viene del mismo lugar que los de calibración. Por eso su error puede caer en cualquier posición de la fila con la misma probabilidad. Si el umbral está en la posición 90 de 100, solo hay un 10 % de probabilidad de que el error nuevo quede por encima.

Teorema (cobertura). Si los datos de calibración y el dato nuevo son intercambiables, el rango que entrega conformal contiene el valor real con probabilidad de al menos 1 − α:   P( valor real ∈ rango ) ≥ 1 − α. Además, si no hay errores repetidos, esa probabilidad es a lo sumo 1 − α + 1/(n+1).

La garantía tiene tres virtudes: no supone ninguna distribución, sirve para cualquier modelo y vale con una cantidad finita de datos. Su único requisito es la intercambiabilidad: que los datos nuevos se parezcan a los de calibración y que el orden en que llegan no importe. Si los datos cambian con el tiempo, el requisito se rompe (sección 7.5).

4. Los cuatro pasos y la función central

Todos los métodos siguen los mismos cuatro pasos (Papadopoulos et al., 2002; Lei et al., 2018):

  1. Separar los datos en entrenamiento, calibración y prueba.
  2. Entrenar el modelo solo con los datos de entrenamiento.
  3. Medir los errores (scores) del modelo en los datos de calibración.
  4. Tomar el umbral q̂ y usarlo para armar el rango de cada caso nuevo.

El paso 4 es una sola función, que se reutiliza en los tres métodos:

def conformal_quantile(scores, alpha):
    n = len(scores)                           # cuántos errores tengo
    k = int(np.ceil((n + 1) * (1 - alpha)))   # qué posición de la fila tomo
    if k > n:                                 # muy pocos datos:
        return np.inf                         #   no puedo prometer nada
    return np.sort(scores)[k - 1]             # ordeno y devuelvo el k-ésimo

Ejemplo a mano. Con 9 errores (0,1; 0,3; 0,4; 0,7; 0,9; 1,2; 1,8; 2,5; 3,1) y una promesa del 80 %: k = (9 + 1) × 0,8 = 8, así que q̂ es el 8.º error más pequeño, 2,5.

¿Por qué n + 1? Porque el caso nuevo también entra en la fila: con 9 errores de calibración hay 10 posiciones posibles. Ese “+1” es lo que hace que la garantía valga con pocos datos. Por eso no sirve usar directamente np.quantile(scores, 0.8): el umbral puede quedar por debajo del necesario.

Lo único que cambia entre los tres métodos es qué se usa como “error”:

Método¿Qué es el “error”?¿Qué entrega?
1. Split conformal (banda fija)La distancia entre el valor real y la predicciónPredicción ± q̂: el mismo margen para todos
2. CQR (banda adaptativa)Cuánto se sale el valor real de una banda “piso–techo”Un margen ancho donde hay duda y angosto donde no
3. Mondrian (umbral por clase)1 − la probabilidad que el modelo le dio a la respuesta correcta, medido por separado en cada claseLa garantía se cumple dentro de cada clase

5. Método 1: split conformal (banda fija)

Datos del ejemplo. Para los métodos 1 y 2 se simularon 3.000 puntos con y = x·sen(x) más un ruido que crece con x: a la izquierda los datos están muy juntos y a la derecha muy dispersos. Reparto: 1.500 para entrenar, 750 para calibrar y 750 para probar. Promesa pedida: 90 %.

# Paso 1. Entreno el modelo (solo con train)
model = XGBRegressor(max_depth=3).fit(X_train, y_train)
# Paso 2. Mido sus errores en calibración
errores = np.abs(y_cal - model.predict(X_cal))
# Paso 3. Saco el umbral q_hat
q_hat = conformal_quantile(errores, alpha=0.10)
# Paso 4. Predicción ± q_hat
pred = model.predict(X_new)
lower, upper = pred - q_hat, pred + q_hat

En palabras: el “error” es cuánto se equivocó el modelo en cada dato de calibración. q̂ es el error que solo se supera el 10 % de las veces (aquí, 3,78). El intervalo es la predicción más y menos ese valor.

Resultado: cubre el 91,5 % de los datos de prueba, es decir, cumple la promesa del 90 %. Su limitación es que el margen es igual para todos los casos (7,56 de ancho), sean fáciles o difíciles.

6. Método 2: CQR (banda adaptativa)

La regresión cuantílica conformalizada (Romano, Patterson & Candès, 2019) busca un margen que se adapte a cada caso.

# Paso 1. Dos XGBoost: uno para el "piso" y otro para el "techo"
q = dict(objective="reg:quantileerror", max_depth=3)
piso  = XGBRegressor(quantile_alpha=0.05, **q).fit(X_train, y_train)
techo = XGBRegressor(quantile_alpha=0.95, **q).fit(X_train, y_train)
# Paso 2. Error = cuánto se sale el dato real de la banda
errores = np.maximum(piso.predict(X_cal) - y_cal, y_cal - techo.predict(X_cal))
# Paso 3. Saco el umbral q_hat
q_hat = conformal_quantile(errores, alpha=0.10)
# Paso 4. Corrijo la banda con q_hat
lower, upper = piso.predict(X_new) - q_hat, techo.predict(X_new) + q_hat

En palabras:

  1. Se entrenan dos XGBoost: uno predice el “piso” (el valor por debajo del cual cae el 5 % de los casos) y otro el “techo” (95 %). Esa banda ya es ancha donde hay duda y angosta donde no.
  2. Pero esa banda no trae garantía. Entonces el “error” es cuánto se sale cada dato real de la banda (negativo si quedó adentro).
  3. Con q̂ se corrige la banda: si cubría de menos, q̂ es positivo y la ensancha; si cubría de más, q̂ es negativo y la estrecha.

Resultado: la banda sin corregir cubría 92,5 % (de más); CQR la estrechó (q̂ = −0,24) y quedó cubriendo el 90,4 %.

6.2 Advertencia: la garantía es un promedio

ZonaBanda fijaCQR
Poco ruido: x entre 0 y 2,5100 %98,6 %
Mucho ruido: x entre 7,5 y 1076,7 %86,5 %

La banda fija cumple el 90 % en promedio, pero lo hace acertando siempre donde es fácil y fallando más donde es difícil. Esto se llama cobertura marginal: la promesa vale para el conjunto de los datos, no para cada zona o subgrupo. CQR reparte mejor los aciertos. Cuando el subgrupo que importa es una clase (por ejemplo, los fraudes), se necesita el método 3.

7. Método 3: Mondrian (umbral por clase), con el caso de fraude

7.1 En clasificación la respuesta es un conjunto

El modelo ya no dice “es fraude” o “no es fraude”. Dice: “estas son las respuestas que no puedo descartar”.

ConjuntoQué significaDecisión
{legítima}El modelo está seguro de que es legítimaNo se alerta
{fraude} o {legítima, fraude}No se puede descartar que sea fraudeSe alerta
VacíoCaso muy raro: ninguna respuesta convenceNo se alerta

Regla de decisión: se alerta si “fraude” está en el conjunto. Con esa regla se pueden usar las métricas del curso: recall (de los fraudes reales, cuántos detecto), precisión (de mis alertas, cuántas son fraude) y matriz de confusión.

7.2 El código, paso a paso

Primero: medir el error en cada transacción de calibración.

# Paso 1. Entreno el XGBoost del notebook 02 (solo con train)
clf = XGBClassifier(n_estimators=300, max_depth=6, scale_pos_weight=spw,
                    enable_categorical=True).fit(X_train, y_train)
# Paso 2. Mido el error en cada transacción de calibración
P_cal = clf.predict_proba(X_cal)                      # 2 columnas: [p(legítima), p(fraude)]
p_real = P_cal[np.arange(len(y_cal)), y_cal]          # la probabilidad de su clase REAL
s_cal = 1 - p_real                                    # el error: lo que le faltó para llegar a 1
La transacción era…El modelo dijo p(fraude) =Probabilidad de la respuesta correctaError
Legítima0,0010,9990,001: acertó
Fraude0,980,980,02: acertó
Fraude0,100,100,90: se equivocó

Un error cerca de 0 significa que el modelo acertó con seguridad; cerca de 1, que se equivocó.

Después: sacar el umbral y armar el conjunto.

# Paso 3. Saco el umbral q_hat
q_unico  = conformal_quantile(s_cal, 0.05)               # MÉTODO 1: con todos
q_legit  = conformal_quantile(s_cal[y_cal == 0], 0.05)   # MÉTODO 3: solo legítimas
q_fraude = conformal_quantile(s_cal[y_cal == 1], 0.05)   # MÉTODO 3: solo fraudes
# Paso 4. Una etiqueta entra al conjunto si su error (1 - p) es <= su umbral
P = clf.predict_proba(X_test)
conjunto_m1 = (1 - P) <= q_unico                 # mismo umbral para las 2 etiquetas
conjunto_m3 = (1 - P) <= [q_legit, q_fraude]     # un umbral para cada etiqueta
# Decisión: alerto si "fraude" (columna 1) quedó dentro del conjunto
alerta = conjunto_m3[:, 1]
MétodoUmbral q̂En la práctica, alerta si…

Es el mismo código. La única diferencia es que Mondrian calcula el umbral de los fraudes solo con los fraudes (Vovk, 2012), y por eso es mucho menos exigente para alertar. En el notebook estos mismos pasos están dentro de las funciones sets_split y sets_mondrian.

7.3 El montaje del ejercicio

  1. Datos: 300.000 transacciones del dataset de fraude del curso (Kaggle, kartik2112); solo el 0,58 % son fraude.
  2. Reparto: 180.000 para entrenar, 60.000 para calibrar (348 fraudes) y 60.000 para probar.
  3. Modelo: el XGBClassifier del notebook 02 (300 árboles, profundidad 6, scale_pos_weight ≈ 172), con PR-AUC de 0,912 en prueba.
  4. Promesa pedida: 95 %.

Cómo leer la figura 3. En las legítimas (izquierda) casi todas las barras están pegadas al 0: el modelo las acierta con facilidad, y por eso su umbral es muy pequeño (0,003). En los fraudes (derecha) la mayoría también está cerca de 0, pero hay varios casos cerca de 1: son fraudes que el modelo no reconoció. Para dejar el 95 % de los fraudes a la izquierda, el umbral tiene que irse hasta 0,949. El eje vertical está en escala logarítmica para que se alcancen a ver las barras pequeñas.

¿Por qué pasa esto? El 99,4 % de las transacciones son legítimas. Con un solo umbral, ellas deciden el cálculo: la promesa del 95 % se cumple en el total, pero solo se detecta el 62 % de los fraudes. Mondrian calcula un umbral solo con los fraudes, así que la promesa se cumple dentro de esa clase: detecta el 96 % de los fraudes. Eso es una garantía de recall.

El precio: más alertas (943 frente a 217) y menos precisión (35 %). A cambio, casi ningún fraude se escapa: de 347 fraudes en prueba, solo 14 quedaron sin alertar.

A más recall prometido, más alertas: con 95 % se alerta el 1,6 % de las transacciones; con 99 %, el 9,3 %, unas seis veces más. El nivel se elige según cuántas revisiones puede atender el equipo.

8. ¿Cuántos datos de calibración se necesitan?

La promesa del 90 % es “en promedio sobre muchos sets de calibración”. Con un set concreto, lo que realmente se obtiene varía un poco, y varía más cuantos menos datos haya (sigue una distribución Beta; Vovk, 2012):

Datos de calibraciónLo que realmente se obtiene (en 9 de cada 10 casos)
50entre 82,6 % y 96,0 %
500entre 87,7 % y 92,1 %
5.000entre 89,3 % y 90,7 %

En Mondrian la cuenta es por clase: los fraudes se calibraron con solo 348 casos, así que su recall real puede moverse 2 o 3 puntos alrededor del 95 %.

9. Cómo usarlo con la librería MAPIE

Para no programarlo a mano, la librería MAPIE (versión 1.x, compatible con scikit-learn) trae los métodos 1 y 2. Siempre son dos pasos: conformalize para calibrar y predict_interval o predict_set para predecir.

from mapie.regression import SplitConformalRegressor, ConformalizedQuantileRegressor
from mapie.classification import SplitConformalClassifier

# MÉTODO 1 en regresión: banda fija
reg = SplitConformalRegressor(model, confidence_level=0.90, prefit=True)
reg.conformalize(X_cal, y_cal)                      # calibrar
y_pred, intervalos = reg.predict_interval(X_test)   # predecir con intervalo

# MÉTODO 2: CQR, con los XGBoost [piso, techo, mediana]
cqr = ConformalizedQuantileRegressor([piso, techo, mediana], confidence_level=0.90, prefit=True)
cqr.conformalize(X_cal, y_cal)

# MÉTODO 1 en clasificación: conjuntos con un umbral único
cls = SplitConformalClassifier(clf, confidence_level=0.95, prefit=True)
cls.conformalize(X_cal, y_cal)
y_pred, conjuntos = cls.predict_set(X_test)

10. Aplicaciones reales y en el trabajo

  • Descubrimiento de fármacos. AstraZeneca lo usa para decidir en qué predicciones sobre moléculas confiar (Norinder et al., 2014).
  • Pronóstico de ventas y energía. Rangos de demanda en lugar de un solo número; viene en librerías como MAPIE y las de Nixtla.
  • Medicina. Una lista corta de diagnósticos posibles, con garantía, para apoyar al especialista.
  • Riesgo y fraude. Priorizar revisiones garantizando el recall de la clase rara, como en el ejemplo.
  • Modelos de lenguaje. Conjuntos de respuestas que contienen una correcta con probabilidad garantizada (Quach et al., 2024).
  • Sistemas autónomos. Zonas donde puede estar un objeto, con garantía, para planear con seguridad.

Aplicación en el trabajo: gastos administrativos bajo NIIF 17

En una aseguradora, la norma NIIF 17 exige separar los gastos atribuibles a los contratos de seguro de los no atribuibles. Cada combinación centro de costos–cuenta contable se clasifica en una de las dos categorías según la política corporativa, y cada vez que aparecen combinaciones nuevas hay que clasificarlas.

Un XGBoost puede aprender la clasificación vigente y sugerir la categoría de las combinaciones nuevas. Mondrian aporta la regla de decisión, con garantía en cada categoría: si el conjunto trae una sola categoría, la combinación se asigna automáticamente y de forma consistente con la política; si trae las dos, es un caso fronterizo que pasa a revisión del experto, con la sugerencia del modelo como apoyo. Para el presupuesto de gastos, CQR permite entregar un rango confiable en lugar de un número único.

12. Conclusiones

  1. Conformal prediction le pone una garantía a cualquier modelo: solo mide sus errores en datos que no vio.
  2. Es sencillo y barato: un set de calibración, una medida de error y una función de cinco líneas.
  3. Banda fija para empezar, CQR cuando la duda cambia de un caso a otro y Mondrian cuando una clase importa más. En fraude, Mondrian detectó el 96 % de los fraudes, frente al 62 % del umbral único.
  4. La garantía vale mientras los datos no cambien: en los meses futuros bajó a 92,7 %. En producción hay que vigilar y recalibrar.

Preguntas probables y respuestas sugeridas

¿En qué se diferencia de calibrar probabilidades? Calibrar busca que una probabilidad de 0,8 signifique 80 %, pero no da una garantía formal ni una regla de decisión. Conformal no necesita probabilidades confiables: solo usa el orden de los casos. Por eso funciona incluso con scale_pos_weight.

¿Por qué no usar simplemente un umbral sobre la probabilidad? Un umbral fijo como 0,5 dio 87 % de recall, pero nadie sabía de antemano cuánto iba a dar. Mondrian es, en el fondo, un umbral (0,051 en el ejemplo), pero elegido de forma que el recall mínimo quede garantizado antes de mirar los datos de prueba.

¿Qué pasa si los datos cambian con el tiempo? Se rompe el requisito y la promesa se debilita, como en el ejemplo (92,7 %). En la práctica se recalibra con datos recientes y se vigila el resultado.

¿Cuántos datos de calibración se necesitan? Con 500, una promesa de 90 % queda entre 88 % y 92 %; con 5.000, entre 89 % y 91 %. En Mondrian la cuenta es por clase.

¿Por qué aparecen conjuntos vacíos? Porque ninguna etiqueta alcanza su umbral. Pasa con modelos muy seguros; son casos atípicos y en el ejemplo no generan alerta.

¿Por qué CQR puede estrechar la banda? Porque q̂ puede ser negativo: si la banda “piso–techo” ya cubría de más (92,5 %), la corrección la ajusta hacia adentro hasta el 90 %.

¿Sirve con un modelo malo? Sí, la promesa se cumple igual, pero los rangos serán muy anchos y poco útiles. Un mejor modelo da rangos más angostos.

¿Garantiza un trato parejo entre grupos? No por defecto, porque la promesa es un promedio. Con Mondrian se garantiza dentro de cada grupo que se defina.

14. Glosario

TérminoSignificado sencillo
Set de calibraciónDatos con respuesta conocida que el modelo no vio al entrenar; se usan para medir sus errores.
Score de no conformidadEl “error” del modelo en un caso: qué tan mal encaja ese caso con lo que el modelo esperaba.
q̂ (q gorro)El umbral: el error que solo se supera α de las veces.
α (alfa)El error que se acepta. Con α = 0,05 se promete acertar el 95 %.
CoberturaPorcentaje de veces que el valor real queda dentro del rango entregado.
Cobertura marginalLa cobertura se cumple en el total de los datos, no en cada subgrupo.
IntercambiabilidadLos datos nuevos se parecen a los de calibración y el orden en que llegan no importa.
RecallDe los fraudes reales, qué porcentaje se detectó.
PrecisiónDe las alertas generadas, qué porcentaje era realmente fraude.
Regresión cuantílicaUn modelo que, en lugar del valor medio, predice un “piso” o un “techo”.
