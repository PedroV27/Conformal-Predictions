Conformal Prediction
El problema

Un modelo nos da un número… pero ¿cuánto confiar en él?

Lo que entrega hoy el modelo

“El gasto de marzo será $1.200 M”
“Esta transacción es fraude con p = 0,83”

Lo que necesita quien decide

“El gasto estará entre $1.050 M y $1.380 M, y acierto 9 de cada 10 veces”
“Con esta regla detecto al menos el 95 % de los fraudes”

  • Un número solo no dice qué tan lejos puede estar la realidad.
  • Las probabilidades de XGBoost sirven para ordenar los casos, pero no son confiables como porcentaje (lo vimos en el notebook 02).
  • Necesitamos un margen de seguridad que se pueda comprobar.

La idea, con una analogía

El empleado nuevo que estima facturas

1

Le muestro 100 facturas cuyo valor real ya conozco y que él nunca ha visto.

2

Anoto cuánto se equivocó en cada una.

3

Ordeno los errores de menor a mayor y miro el error número 90: digamos, $80 mil.

4

Desde hoy, si dice “vale $1 millón”, yo digo: “entre $920 mil y $1.080.000”, y acierto el 90 % de las veces.

Conformal Prediction
La promesa

Qué garantiza conformal prediction

P( valor real ∈ rango que entrego ) ≥ 1 − α

Sin supuestos de distribución

No importa si los datos son normales, sesgados o con valores extremos.

Para cualquier modelo

Regresión logística, XGBoost o una red neuronal: se usa como caja negra.

Con pocos o muchos datos

La garantía vale con los datos que tengo, no solo “con infinitos datos”.

Un solo requisito: que los datos nuevos se parezcan a los de calibración (técnicamente, que sean intercambiables). Vovk, Gammerman & Shafer (2005).
Conformal Prediction
Por qué funciona

Un argumento de ranking

  • Pongo en fila los errores de calibración, de menor a mayor.
  • El caso nuevo es “uno más del grupo”: su error puede caer en cualquier posición de la fila con la misma probabilidad.
  • Si pongo el umbral en la posición 90 de 100, solo hay un 10 % de probabilidad de que quede por encima. Ese es todo el teorema.
Conformal Prediction
El algoritmo

Siempre los mismos cuatro pasos

1

Separar los datos en entrenamiento, calibración y prueba.

2

Entrenar el modelo solo con los datos de entrenamiento.

3

Medir los errores (scores) del modelo en calibración.

4

Tomar el umbral q̂ y usarlo para armar el rango de cada caso nuevo.

q̂ = el error en la posición ⌈(n+1)(1−α)⌉

¿Por qué n+1? Porque el caso nuevo también entra en la fila: con 9 errores de calibración hay 10 posiciones posibles.

Resultado garantizado: la cobertura queda entre 1 − α y 1 − α + 1/(n+1).

Es barato: un solo entrenamiento y ordenar n números. Se agrega a cualquier modelo que ya tengamos.

En código · la pieza central

Todo el método cabe en una función

import numpy as np

def conformal_quantile(scores, alpha):
    n = len(scores)                           # cuántos errores tengo
    k = int(np.ceil((n + 1) * (1 - alpha)))   # qué posición del ranking tomo
    if k > n:                                 # muy pocos datos:
        return np.inf                         #   no puedo prometer nada
    return np.sort(scores)[k - 1]             # ordeno y devuelvo el k-ésimo

errores = np.array([0.3, 1.2, 0.7, 2.5, 0.1, 0.9, 1.8, 0.4, 3.1])
conformal_quantile(errores, alpha=0.2)   # 9 errores, quiero 80 %
# k = (9 + 1) x 0.8 = 8  ->  el 8.º más pequeño  ->  2.5
  • Recibe los errores de calibración y el error que acepto (α).
  • Ordena los errores y devuelve el de la posición k: ese es q̂.
  • No mira el modelo ni supone nada sobre los datos.
  • Es la misma función para los tres métodos. Solo cambia qué llamamos “error”.

Método 1 · paso a paso

Split conformal: predicción ± un margen fijo

from xgboost import XGBRegressor

# Paso 1. Entreno el modelo (solo con train)
model = XGBRegressor(max_depth=3).fit(X_train, y_train)

# Paso 2. Mido sus errores en calibración
errores = np.abs(y_cal - model.predict(X_cal))

# Paso 3. Saco el umbral q_hat
q_hat = conformal_quantile(errores, alpha=0.10)

# Paso 4. Predicción ± q_hat
pred = model.predict(X_new)
lower, upper = pred - q_hat, pred + q_hat
  • Son exactamente los cuatro pasos de antes.
  • El “error” es cuánto se equivocó el modelo: |real − predicho|.
  • q̂ es el error que solo se supera el 10 % de las veces.
  • El intervalo final es la predicción más y menos q̂.
Limitación: el margen es igual para todos los casos, sean fáciles o difíciles.
Conformal Prediction
Método 2 · paso a paso

CQR: un margen que se adapta a cada caso

# Paso 1. Dos XGBoost: uno para el "piso" y otro para el "techo"
q = dict(objective="reg:quantileerror", max_depth=3)
piso  = XGBRegressor(quantile_alpha=0.05, **q).fit(X_train, y_train)
techo = XGBRegressor(quantile_alpha=0.95, **q).fit(X_train, y_train)

# Paso 2. Error = cuánto se sale el dato real de la banda
errores = np.maximum(piso.predict(X_cal) - y_cal,
                     y_cal - techo.predict(X_cal))

# Paso 3. Saco el umbral q_hat
q_hat = conformal_quantile(errores, alpha=0.10)

# Paso 4. Corrijo la banda con q_hat
lower = piso.predict(X_new) - q_hat
upper = techo.predict(X_new) + q_hat
  • Entreno dos XGBoost: uno predice el “piso” (5 %) y otro el “techo” (95 %).
  • Esa banda ya es ancha donde hay duda, pero no trae garantía.
  • El “error” es cuánto se sale el dato real de la banda.
  • Con q̂ corrijo la banda: la ensancho si cubría de menos o la estrecho si cubría de más.

Advertencia clave

La garantía es un promedio, no se cumple en cada zona

  • La banda fija acierta el 100 % donde hay poco ruido y solo el 77 % donde hay mucho.
  • En promedio da 91 %: cumple, pero de forma desigual.
  • CQR sube la zona difícil a 87 %.
  • Si el grupo que me importa es una clase (como los fraudes), necesito el método 3.
Conformal Prediction
Clasificación

Ahora la respuesta es un conjunto de etiquetas

El modelo ya no dice “es fraude” o “no es fraude”. Dice: “estas son las respuestas que no puedo descartar”.

{legítima}

Seguro de que es legítima.
No alerto.

{fraude} o {legítima, fraude}

No puedo descartar fraude.
Alerto para revisión.

{ } vacío

Caso muy raro: ninguna respuesta convence.
Aquí no alerto.

Regla de decisión: alerto si “fraude” está en el conjunto. Así puedo medir con las métricas del curso: recall, precisión y matriz de confusión.

Método 3 · paso a paso (1 de 2)

Primero: medir el error en cada transacción

# Paso 1. Entreno el XGBoost del notebook 02 (solo con train)
clf = XGBClassifier(n_estimators=300, max_depth=6,
                    scale_pos_weight=spw,
                    enable_categorical=True).fit(X_train, y_train)

# Paso 2. Mido el error en cada transacción de calibración
P_cal = clf.predict_proba(X_cal)    # 2 columnas: [p(legítima), p(fraude)]

# de cada fila tomo la probabilidad de su clase REAL...
p_real = P_cal[np.arange(len(y_cal)), y_cal]

# ...y el error es lo que le faltó para llegar a 1
s_cal = 1 - p_real

El error es lo que le faltó al modelo para darle 100 % a la respuesta correcta. Tres casos de ejemplo:

Era…El modelo dijo p(fraude) =Error
Legítima0,0010,001: acertó
Fraude0,980,02: acertó
Fraude0,100,90: se equivocó
Error cerca de 0 = el modelo acertó con seguridad. Error cerca de 1 = el modelo se equivocó.

Método 3 · paso a paso (2 de 2)

Después: un umbral para cada clase

# Paso 3. Saco el umbral q_hat
q_unico   = conformal_quantile(s_cal, 0.05)               # MÉTODO 1: con todos
q_legit   = conformal_quantile(s_cal[y_cal == 0], 0.05)   # MÉTODO 3: solo legítimas
q_fraude  = conformal_quantile(s_cal[y_cal == 1], 0.05)   # MÉTODO 3: solo fraudes

# Paso 4. Una etiqueta entra al conjunto si su error (1 - p) es <= su umbral
P = clf.predict_proba(X_test)
conjunto_m1 = (1 - P) <= q_unico                 # mismo umbral para las 2 etiquetas
conjunto_m3 = (1 - P) <= [q_legit, q_fraude]     # un umbral para cada etiqueta

# Decisión: alerto si "fraude" (columna 1) quedó dentro del conjunto
alerta = conjunto_m3[:, 1]
recall_score(y_test, alerta), precision_score(y_test, alerta)

Método 1: un solo umbral

q̂ = 0,003, calculado con las 60.000. Solo alerta si p(fraude) ≥ 0,997: casi nunca.

Método 3: Mondrian

Legítimas: q̂ = 0,003 (59.652 casos).
Fraudes: q̂ = 0,949 (348 casos).
Alerta si p(fraude) ≥ 0,051.

Es el mismo código. La única diferencia: Mondrian calcula el umbral de los fraudes solo con los fraudes, y por eso es mucho menos exigente para alertar.

Conformal Prediction
¿Por qué pasa esto?

El 99 % legítimo “tapa” a los fraudes

Método 1: un solo umbral

Mezcla todos los errores. Como casi todo es legítimo, el umbral lo deciden las legítimas.

La promesa del 95 % se cumple en el total, pero solo se detecta el 62 % de los fraudes.

Método 3: Mondrian

Calcula un umbral solo con los fraudes y otro solo con las legítimas.

La promesa se cumple en cada clase: detecta el 96 % de los fraudes. Eso es una garantía de recall.

El precio: más alertas (943 frente a 217) y menos precisión. A cambio, casi ningún fraude se escapa.
Conformal Prediction
Ejemplo · el precio de pedir más

A más recall prometido, más alertas

Mondrian cumple lo que promete en cualquier nivel (sigue la diagonal). Pero prometer 99 % en vez de 95 % sube las alertas de 1,6 % a 9,3 % de las transacciones: unas 6 veces más.

¿La promesa se sostiene en el futuro?

Cierre

Tres ideas para llevarse

1. Conformal le pone una garantía a cualquier modelo: solo mide sus errores en datos que no vio.

2. Banda fija para empezar, CQR cuando la duda cambia y Mondrian cuando una clase importa más.

3. La garantía vale mientras los datos no cambien: en producción, vigilar y recalibrar.
